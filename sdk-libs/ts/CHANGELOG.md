# Changelog

## 0.1.0-alpha — unreleased

The custom ring surface of `@heliuslabs/zolana` moves into `@heliuslabs/zolana-custom-rings`, built on `@heliuslabs/zolana` as a pinned peer, and `CustomRingClient` adds the ring proofs and the ring indexer reads to a `ZolanaClient`. A ring holds its rules and role keys in one `RingPolicy` account, its lists and mint settings in Storage Program records and each owner's nullifier key in an audit credential the shielded pool stores, and one key catalog proves every transfer rail. Every transfer seals one auditor stream under its transaction viewing key, a frame past one transaction settles from a buffer, and a wallet can read a whole ring with no tag read.

Breaking

- `DELIVERED_AUDIT_CAPACITIES` → `TRANSFER_OUTPUT_CAPACITIES`, `ConfigAuthorityAuth` → `PolicyAuthorityAuth`, the refusal key `notConfigAuthority` → `notPolicyAuthority` and the error key `invalidChangeBits` → `bodilessExit`.
- List enrolment is list approval. `getPendingEnrolments` → `getPendingListApprovals` with a `pending` page, `refuseEnrolment` → `refuseListApproval`, `signPendingEnrolmentsRequest` and `signRefuseEnrolmentRequest` → `signPendingListApprovalsRequest` and `signRefuseListApprovalRequest`, the status `awaitingAuthority` → `pendingListApproval`, `WalletRecordUpdate.awaitingAuthority` → `awaitingListApproval`, `ENROLMENT_LISTS` → `AWAITABLE_LISTS`, `RingEnrolmentAction` → `PolicyAuthorityAction`, `enrolmentAttestation` → `policyAuthorityAttestation`, the `PendingEnrolment` types → `PendingListApproval`, the refusal keys `enrolmentLists`, `enrolmentBatch`, `unknownEnrolment` and `enrolmentWindow` → `invalidAwaitedLists`, `listApprovalBatch`, `unknownListApproval` and `listApprovalWindow`, and the policy authority signs over `zolana/ring-rpc-policy-authority` → deploy this release's Ring RPC with the SDK and rename each call.
- `QueueEntry` → `RecordWrite`, `queueChain` → `writeChain`, `queueEntryHash` → `recordWriteHash` and `recordUpdateQueueEntry` → `recordUpdateWrite`, the hashes stay the same.
- The error keys `invalidCuratorRegistry`, `invalidCoSignerThresholds`, `invalidAnonymousOutput`, `mergeDisclosureWidth`, `policyAlreadySet`, `dataFreeBodyLength`, `thresholdsWithoutWithdrawals` and `changeTagNotZero` are gone, no program path raises them.
- `RingProgramError` drops `invalidTrackingRegistry`, `trackingRootBelowFloor` and `saltedSourceOtherTracking`, and `StorageProgramError` drops `nonCanonicalViewingKey`, `invalidTrackingRegistry`, `invalidTrackingAuthorization`, `enrollmentAlreadyApplied`, `enrollmentKeyFinal`, `enrollmentProofShape` and `noEnrollmentsNamed`, no program path raises them.
- `@heliuslabs/zolana/ring` and the custom ring, auditor and key registry
  exports of the `@heliuslabs/zolana` entry points move here → import them from
  `@heliuslabs/zolana-custom-rings` or its `client` and `keypair` entry points.
- `ZolanaClient`'s `proveCustomRing*`, `proveIndexedRingPolicy`, `proveIndexedRingDeposit`, `getRingSpendRecord`, `getRingKeyRegistryEntry` and `getRingKeyRegistryRegisterProof` are gone and `CustomRingClient.proveRing(request)` proves every ring circuit from a `RingProofRequest` → create the client with `createCustomRingClient(config)`, implement `proveRing` in a custom `RingProver` and the reads in a custom `RingRecordReader`, omit `provingKeys`, and import the rule table codecs, list writers and statements from `@heliuslabs/zolana-custom-rings/advanced`.
- Ring instructions, accounts, proofs and frames change format, `RingInstructionTag` and `RingScheme` take new values and the merge key is `custom-ring-merge` → deploy this release's ring program, prover and keys together, reissue every `RingAddress`, rebuild each wallet document with a sync, and re-register each ring under its newly derived auditor key.
- `initializeRingInstruction` replaces `initializeRingConfigInstructions`, `createRingConfigInstruction`, `initSppRingConfigInstruction` and `createRingPolicyInstruction`, `updateRingPolicyInstruction` replaces `setRingPolicyRulesInstruction` and `setRingPolicySourceInstruction`, `updateRingAuthorityInstruction` replaces `setRingAuthorityInstruction`, `fetchRingCoSignerRecord` replaces `fetchRingCoSigner`, and `fetchRingPolicy` reads the rules, the `RingRoles` and the delegate → create the records registry first, pass four distinct nonzero `roles` and the table as `policy` to `initializeRingInstruction`, and appoint each co-signer with its own `setRingCoSignerInstruction`.
- `updateRingPolicyInstruction` takes the ring account as read in `current` and appends the records and curator it holds after the registries the write names, the program reads each registry a salted list of the proposed account reads → pass the account `fetchRingPolicy` returns.
- `WalletRecordUpdate` and `AuthorityRecordUpdate`, sent with `RingRpc.submitRecordUpdate`, write lists, mint settings and reader grants in place of `buildRingListWriteTransaction`, `grantReadAccessInstruction` and `revokeReadAccessInstruction`, each mint's limits live in a `MintPolicy` record keyed by `memberOfAsset(mint)`, and a rule table refuses a mixed polarity row, a row over several absences, an inverted polarity and a rule over the `reader` list with `RING_RULE_TABLE_INVALID` → sign each record update, send it to Ring RPC and rewrite a refused rule.
- An owner's nullifier key lives in its ring audit credential in place of a tracking registry, so `enrollInstruction`, `proveEnrollment`, `applyEnrollmentsInstruction`, `resolveRingRecipient`, `fetchTrackingRegistry` and the tracking reads of `CustomRingClient` are gone, `fetchRingSealedKey` takes the `owner`, `ownerGrantInstruction` takes `ringProgramId`, `RingAddress` carries its `listSalt`, `ListId` gains `privateBlock` and `privateAllow` in place of `recovery` and `escrow`, and a spend raises `RING_LIST_SALT_MISSING` for an enrolled owner with no salt → enroll with `prepareEnrollment`, pick payment keys with `resolveRecipientKeys`, build an address with `RingAddress.enrolled(holder, ringProgramId, listSalt)` and pass `listSalts` naming every enrolled owner a salted list reads.
- Transfer frames, deposits and merges name their credential roots by a `CredentialRead`, every proof request carries a `CredentialRoots` table with one opening per live owner, `ProvenRingTransfer` and `ProvenRingDeposit` bind `credentialRoots` and a merge request carries its owner's `credential` → give every transfer, deposit and merge client the `CredentialClient` reads and rebuild a stored frame or request.
- A transfer takes `TransferProofRequest` under the `RING_KEYS` catalog, co-signers travel as `[record, signer]` pairs until every demanded class is covered, `RingDepositClient` reads record pools, and `PreparedRingDeposit.prove` raises `RING_DEPOSIT_FRAME_REUSED` on a second call → pass `cosigners` covering every demanded class, give the deposit client `getStorageRecordPool` and the credential reads of `CredentialClient`, and prepare a new deposit per attempt.
- `auditRingTransaction` takes the `layout` of a `ConfirmedRingTransaction`, `AuditStreamLayout` fixes every auditor ciphertext length, `sealRingDisclosure` and `openRingDisclosure` work under a `salt`, `InputOpening` adds `unseenHash` and `unresolvedReal`, and every signed `RingRpc` read takes a `RingReadTarget` → implement `confirmedTransaction` in a custom origin, handle the new kinds, and pin the Ring RPC service key in each `RingReadTarget`.
- `AnonymousSync.fetch` scans each ring a `ViewingHistory` names and reads tags only for deposits and merges, `AnonymousWallet` stores notes, spends, claims and positions in one document, `RingKeys` requires `ringTagMatches`, and `RingPaymentRequest` carries an optional `depositTag` → call `ViewingHistory.withRing` when a key enrolls, store the wallet as one document, implement `ringTagMatches` in a custom holder and ask each recipient for a new request.
- `RingTagKind` adds `confidential`, and `syncRingWallet` reads a confidential ring output through `ringTagMatches` in place of `ringDeliverySecrets` → answer the `confidential` kind in a custom holder's `ringTagMatches`.
- `openReply` returns a `ReplyClaim` holding the `claimed` metadata, and `AnonymousScan.replyClaims` of `ReplyClaim` is `senderClaims` of `SenderClaim` with a `claim` → read a claimed sender through `claim.claimed`, an unverified claim no authorization reads.
- A wallet reads its zero-key notes apart from its balance through `AnonymousWallet.exposedNotes`, spending one raises `RING_ZERO_KEY_INPUT_UNNAMED` off the `spendPublic` rail, and a shortfall they could cover raises `RING_UNFUNDED_PAST_EXPOSURE` → pass `spendPublic` when the user accepts that the wallet becomes public, on `CustomRingTransfer` it returns a `PublicOwnerTransfer`.
- `PendingRelaySignature.sign` signs only a message that holds what the wallet requested and raises `RING_RELAY_MESSAGE_INVALID` naming a `RelayMessageMismatch`, `PendingRelaySignature.verify` takes the signer, and `PreparedRingDeposit.prepareRelay` takes `depositorSigner` and `prepareRingMergeRelay` takes `signer` → pass those signers and handle each mismatch.
- `PreparedAuthorityTransfer` takes one `RequestedAuthorityTransfer` whose `AllowedNullifiers` the delegate admits from its own openings of exactly the requested sources, and a message that spends any other note raises the mismatch `SpendsUnrequestedNote` → admit each source's notes with `AllowedNullifiers.admit` and pass the set.
- `CompressedProof.toCustomRingProof()` is gone → call `customRingProof(proof)`
  with the prover's proof.
- `syncRingWallet` and `openRingNotes` open ring deposits, an audited one
  through the ring capsule, and `syncWallet` no longer does → sync ring
  wallets with `syncRingWallet` and drop `depositPayloadDecoder` from the
  `syncWallet` config.
- A relayed transfer seals under the row its public counts select, and Ring RPC refuses it with `RingRpcRefusal.resealNarrow` or `resealWide` when a salted or asset record read selects a key whose stream differs → prepare the relay again with that `sealRow` and sign the new message.
- `RingRpc` now posts each JSON-RPC method beneath its base URL and accepts
  `RingRpcOptions.apiKey` or the URL's `api-key`, while `RingRpc.url` omits the key;
  service clients reject malformed or conflicting credentials during construction
  and preserve unrelated URL queries → forward method paths unchanged and supply
  the API key in one place.
- `syncRingWallet` takes the `AnonymousWallet` the anonymous scan also stores, its `ViewingHistory` keys gain a `tagPosition` and its document a required `mergeRetries` list under the names the Rust client uses, and `openRingNotes` returns notes of unregistered mints in `pendingOpenings` in place of a `pending` count → create the wallet with `AnonymousWallet.create(wallet, ViewingHistory.create(viewingPublicKey, createdAt))`, store `toJson()` after each sync, and rebuild each stored document with a sync.
- `MergeLedger`, its `ConfirmedMerge`, `MergeInput`, `KnownMergeInput`, `MergeTransition` and `AuditedMergeOutput` types, `recoverMergeOpening`, `MergeAuditorOpening`, `KnownUtxos.merged` and the `merged` kind of `InputOpening` are gone, a ring merge record opens its output in full → read a merge output from `KnownUtxoIndex.utxo` by its commitment.
- `openAuditorRegions`, the `EscrowedKeys` type and the error code `RING_ANONYMOUS_RECIPIENT_CURVE` are gone, `openAuditorRegions` opened an unsalted schedule no transfer stream uses → open an auditor stream with `openRingDisclosure` and drop handling of that code.
- The auditor envelope carries `AuditEnvelope.addressInputBits` after `R`, its head grows by eight bytes and every record and tail counter moves with it, `R` counts notes alone, `TransferProofRequest` sends `inputNullifierChain` and `inputNullifiers` in place of `addressChain`, the transfer statement binds `inputNullifierChain` after `inputCount`, `DecryptedRingInput.real` is `class`, and an audited address input reads the `address` kind of `InputOpening` → deploy this release's ring program, prover, keys and Ring RPC together and handle the `address` kind.
- `RingTransactionSubmission.sendPersisted`, `reconcileRingSubmissions` and `closeAbandonedFrameBuffers` take a `RingBufferLedger` as `buffers`, holding each buffer write and close until its signature resolves → load one with `RingBufferLedger.load(store)` from its own store beside the wallet store and pass it to all three.

Added

- `syncRingWallet` raises `RING_HELD_KEY_NOT_IN_HISTORY` before any ring read when the keys hold a viewing key the wallet's `ViewingHistory` has no entry for, so add that key with `withRotatedKey` or `withImportedKey` first.
- `RingRpcRefusal.budgetUnset` names `-32210`, a Ring RPC whose operator set no relay budget refuses a relayed enrollment, a buffered frame and a token account create with it.
- `RingRpcRefusal.alreadyEnrolled`, `registerKeyProof` and `enrollmentRefused` name `-32213` to `-32215`, a relayed enrollment of an owner already enrolled, one whose RegisterKey proof does not verify, and one the chain refuses in simulation.
- `prepareRingTransferRelay`, `prepareRingExitRelay`, `prepareRingEntryRelay`, `prepareRingWithdrawalRelay`, `prepareRingMergeRelay` and `prepareEnrollRelay` send an operation through the Ring RPC relay, and `createRingTransferSubmission`, `createRingExitSubmission`, `createRingEntrySubmission`, `createRingWithdrawalSubmission` and `createRingDepositSubmission` prove and send one with no relay.
- `BufferedFrame` and `withBufferedSettlement` settle a frame past one transaction from a buffer its payer writes, `closeAbandonedFrameBuffers` returns the rent of an abandoned buffer, and `TransactionFit` and `decideAddressCeiling` report and refuse a transaction before any proof, counting the `CredentialTrees` a transfer reads.
- `CoSignerApproval` with `CoSignerRule` and `ApprovalOpening` lets an outside co-signer read the proven bits or exact totals under `withExactApproval`, `OwnerApproval` with `RelayTransferTerms` lets a public owner check its own slots, and `FunderApproval` with `RelayFunderTerms` lets a public funder check its deposit legs.
- `RingRpc.getWalletStatus`, `RingRpc.getWalletActivity` and `RingRpc.getSpendCoverage` read a wallet's notes, its history and a ring's unresolved spends, and `ringFullScan` and `RingAuditPage.skipped` read a whole ring with no tag read and list each row that does not open.
- `rotateViewingKey` moves a wallet's `LocalRingKeys` and `ViewingHistory` to a new viewing key and `LocalRingKeys.rotate` keeps every earlier key, so notes sealed to an old key still open, `updateViewingKey` builds the owner's zolana `UPDATE_KEYS` for the new key and raises `RING_VIEWING_HISTORY_NOT_CURRENT` for a holder ahead of its history, and `confirmViewingKey` raises `RING_VIEWING_KEY_NOT_PUBLISHED` until the user record holds the new key.
- `resolveCredential` reports whether an owner holds an audit credential in a ring as `present` with the proven credential, `absent` with a proof `checkAbsenceFloor` refuses below a floor, or `unknown` when the indexer has not served what the chain holds, and raises `RING_CREDENTIAL_INVALID` when the chain contradicts the indexer and `RING_CREDENTIAL_MISMATCH`, `RING_CREDENTIAL_NULLIFIER_KEY_MISMATCH` or `RING_CREDENTIAL_LIST_TAG_MISMATCH` for a credential of another ring or owner, key or tag.
- `resolveRecipientKeys` picks the nullifier and viewing keys a payment to a `RingAddress` seals under, takes the zero key only for an owner proven not enrolled or, under `zeroKeyToEnrolled`, for an enrolled owner with a registered viewing key, and raises `RING_CREDENTIAL_UNKNOWN` when enrollment cannot be decided.
- `InputMap`, `InputClass`, `envelopeInputMap`, `ADDRESS_INPUT_BITS_LEN`, `ENVELOPE_HEAD_LEN` and `MAX_INPUT_CLASS` from `@heliuslabs/zolana-custom-rings/advanced` classify each published input as a note, an address or a dummy and refuse a map SPP would not publish.
- `resolveViewingKey` reads an owner's current viewing key from the user registry, returns `undefined` only when the owner has not registered, and refuses a malformed key or a nullifier key other than the one passed.
- `resolveCredentials` answers several owners from one snapshot that keeps every present credential of a tree under one root and every absence under one address root, so one proof can bind them all, and `CredentialRead` and `CredentialRoots` from `@heliuslabs/zolana-custom-rings/advanced` encode the roots a frame names.
- `prepareEnrollment` proves a ring `Enroll` that creates the owner's audit credential with its RegisterKey proof and the SPP proof of the credential output, prepends zolana `REGISTER` when the owner holds no user record, and raises `RING_ALREADY_ENROLLED` for an owner `resolveCredential` finds present, the retryable `RING_ENROLLMENT_STATUS_UNKNOWN` when it answers unknown and `RING_ENROLLMENT_KEY_MISMATCH` for a user record under another nullifier key, `enrollCredentialInstruction` builds the same instruction for a PDA owner's CPI with a separate payer, `enrollmentSubmission` saves each attempt in the wallet before its broadcast, and `prepareEnrollmentRelay` raises `RING_RELAY_NEEDS_USER_RECORD` for an owner with no user record while it and `RelayEnrollInputs` name the output tree.
- `RingMergeSettingsRequest` signs an owner's merge settings for a mint and `RingRpc.setMergeSettings` sends them, a zero `targetNoteCount` stops Ring RPC merging that mint, and `RingRpcRefusal.sourceNote` names `-32227`, a recovered delegate note its source does not own.
- `RingRelaySpend.sealRow` and `RingRelayInput.sealRow` seal a relayed transfer under a named `SealRow`, and `RingRpcRefusal.resealNarrow` and `resealWide` name `-32211` and `-32212`.

Fixed

- `recoverRingMemberNotes` failed on one output no registered asset rebuilds and on one row it could not decode, and it lost every zero-key note and every merge output whose seed the nullifier key does not derive, now that commitment stays in `unopened`, a row left unread raises `RING_RECOVERY_INCOMPLETE` once the read is done, and each owned note opens from the auditor's record alone.
- `syncRingWallet` refused every sync after a payment of an unregistered mint arrived and read the whole ring history on each sync, now that note waits in `AnonymousWallet.pendingOpenings()` until its mint registers and a later sync reads only rows past its last position.
- A hand-built `RuleTable` skipped the checks `decodeRuleTable` runs, now policy writes, `policyTableProofInputs` and its hash rerun `buildRuleTable` and refuse such a table with `RING_RULE_TABLE_INVALID`.
- `buildRingMergeTransaction` and `PreparedRingDeposit.prepare` on an anonymous ring refused a PDA owner before any proof, now both build for one, and a zero-key merge names the PDA as the signer its program signs through CPI.
- `LocalRingKeys.destroy` left the list salt key usable, now it wipes that key too and every method needing a secret raises `KEYPAIR_INVALID_SECRET_KEY` afterward.
- A restarted wallet could read its upload buffer as abandoned while a write or close it had sent could still land, now `closeAbandonedFrameBuffers` waits until each such write and close resolves.
- A submission gave up on a proof refused for an address root below a salted source's floor, now it proves again after `absenceRootBelowFloor` as after a revoked root.
